# AI 챗봇 시연 시나리오 (11/25 리허설용 초안)

- 소요: 약 7분 · 진행: C(화면) / B(백엔드 설명)
- 준비: 백엔드 Docker(`feat/ai-chatbot-backend`) + MySQL 시연 데이터, 프론트 `pnpm dev`(http://localhost:5173), 관리자·창고 담당 계정 각 1개
- 표시 `[유통기한]` 은 B의 유통기한 조회가 들어오면 포함, 아니면 건너뜀

## 시연 전 점검 (10분 전)

1. `AI_TEST_USERNAME=… AI_TEST_PASSWORD=… pnpm test:ai --only LS,INV,WH` 로 핵심 케이스 PASS 확인
2. 시연에 쓸 상품명·창고 번호를 보고서의 '실제 데이터 변수'에서 확인해 아래 질문에 채워 두기
3. 브라우저 확대 125%, 챗봇 패널 닫힌 상태로 대시보드에서 시작
4. 비상용: Gemini 장애 시 보여 줄 캡처(프로젝트 공유 폴더 `chatbot/images/`) 준비

## 예상 질문과 답

- **AI가 숫자를 틀리면?** 숫자는 DB 조회 결과를 그대로 넘기고, 화면에서 근거 데이터를 같이 보여 줘서 바로 대조할 수 있습니다. 회귀 테스트도 실제 조회값과 비교합니다.
- **응답이 느린 이유?** Gemini를 두 번(함수 선택, 답변 생성) 부릅니다. 보통 수 초, 최대 약 90초에서 끊고 다시 시도를 안내합니다.
- **권한이 없는 데이터를 물으면?** 서버가 JWT 역할로 막고, 화면은 '조회 권한이 없어요'를 보여 줍니다.
- **데이터를 바꿀 수 있나?** 조회 함수만 등록되어 있어 불가능합니다.

## 비상 시나리오

- Gemini 503이 연속으로 나면: 오류 메시지 자체를 시연(10번)으로 돌리고, 나머지는 캡처로 설명
- 백엔드가 안 뜨면: 프론트만 켜서 '서버에 연결할 수 없어요' 처리 + 캡처로 진행
