# AI 챗봇 시연 시나리오 (약 7분)

- 진행 : 화면 시연 1명, 백엔드 구조 설명 1명
- 환경 : **로컬 Docker**. 실행 순서는 [`local-setup.md`](./local-setup.md)
- 준비 : 백엔드 `feat/ai-chatbot-backend` + 시연 데이터(본사 창고, 테스트 해열진통제 650mg 등), 프론트 `pnpm dev`(http://localhost:5173), 관리자·영업·창고 담당 계정 각 1개
- 표시 `[유통기한]` : 유통기한 조회(`EXPIRY_ENABLED = true`)가 확정됐을 때만 진행, 아니면 건너뜀

## 시연 전 점검 (10분 전)

1. `AI_TEST_USERNAME=… AI_TEST_PASSWORD=… pnpm test:ai --only BE` 로 시연 데이터 3개 케이스만 PASS 확인 (전체 29개는 AI 호출 한도를 쓰므로 시연 직전에는 돌리지 않는다)
2. 브라우저 확대 125%, 챗봇 패널 닫힌 상태로 대시보드에서 시작
3. 비상용 : AI 장애 시 보여 줄 화면 캡처 준비

## 예상 질문과 답

- **AI가 숫자를 틀리면?** 숫자는 DB 조회 결과를 그대로 넘기고, 화면에서 근거 데이터를 같이 보여 줘서 바로 대조할 수 있습니다. 회귀 테스트도 실제 조회값과 비교합니다.
- **응답이 느린 이유?** Gemini를 두 번(함수 선택, 답변 생성) 부릅니다. 보통 수 초이고, 운영 CloudFront 30초 제한에 맞춰 호출당 12초에서 끊고 다시 시도를 안내합니다.
- **권한이 없는 데이터를 물으면?** 서버가 JWT 역할로 막고, 화면은 '조회 권한이 없어요'를 보여 줍니다.
- **데이터를 바꿀 수 있나?** 조회 함수만 등록되어 있어 불가능합니다.
- **API 키는 어디에?** 백엔드 환경 변수(`GEMINI_API_KEY`)에만 있고, 프론트 코드와 저장소에는 없습니다.

## 비상 시나리오

- AI 503·429가 연속으로 나면 : 오류 메시지 자체를 시연(10번)으로 돌리고, 나머지는 캡처로 설명
- 백엔드가 안 뜨면 : 프론트만 켜서 '서버에 연결할 수 없어요' 처리 + 캡처로 진행
